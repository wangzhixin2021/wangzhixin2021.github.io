TCP四次挥手-close（一）

发表于 2026-03-08 分类于 linux6.6内核 阅读次数：
我们在写网络编程时，关闭连接时都要使用close来进行关闭，我们看下close做了些什么。

close系统调用

我们首先来看下close系统调用的入口，可以看到__do_sys_close，首先通过传入的fd,调用close_fd_get_file拿到其对应的file结构。调用flip_flush进一步调用具体文件类型在 file_operations 中注册的 flush 回调（file->f_op->flush），从而执行与 进程关闭该 fd 相关的清理逻辑。__fput_sync会减 file 的引用计数。当引用计数降为 0 时，VFS 才会真正释放该文件对象，并调用 file_operations->release，对于 socket 来说最终会进入 sock_release，并进一步执行 tcp_close 完成 TCP 连接的真正关闭。

close_fd_get_file从当前进程的pcb的files里取出fd对应的文件对象。

pick_file从pcb的fdt上将fd对应的文件对象取出，并从fdt的fd位置置为空、fd置为未使用状态

filp_flush 的作用并不是关闭底层对象，而是清理 与当前进程绑定 的 fd 相关状态（如记录锁和通知机制），真正销毁文件对象并释放资源是在随后 __fput_sync 触发的 file_operations->release 中完成的，对于 socket 来说，TCP 连接的关闭（FIN 发送、状态机转换）发生在 release 阶段，而不是 flush 阶段。

__fput_sync对文件对象的引用计数减1,如果引用计数为0,则返回true,继续调用__fput；若引用计数不为0,则返回false,直接返回。

__fput 才是 VFS 对象生命周期的结束，执行各种资源的释放操作。我们重点关注其中的file->f_op->release，socket的f_op是socket_file_ops，即sock_close。

在sock_close中，使用SOCKET_I根据inode找到对应的socket结构，然后调用__sock_release。

__sock_release标志着 VFS 文件对象与网络协议栈的分界点，在该函数中，VFS 不再参与资源管理，而是通过 proto_ops->release 将控制权交给具体协议实现。首先从socket结构的ops中取出协议操作集合结构，tcp是inet_stream_ops，udp是inet_dgram_ops。调用ops的release，一般是inet_release，这里是真正协议关闭入口。

在inet_release中，首先从socket上取出对应的sock结构，如果是用户态创建的socket，那就过下bpf。然后遍历socket加入的所有组播组，发送 IGMP Leave 报文，退出组播组。
